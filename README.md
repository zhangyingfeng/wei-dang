# 微档

「微档」，即微信公众号作者归档。这是[知档](https://github.com/zhangyingfeng/zhi-dang)（知乎作者归档工具）在微信公众号场景下的姊妹项目，目标和边界完全一致：**帮助公众号作者把自己账号下已经发布过的文章，安全地保存成本地 Markdown/Word 归档，并继续由作者自己控制**。

## 微档不是爬虫，是用户授权的归档工具

和知档一样，微档不采集别人的公众号内容，也不做大规模抓取——它只在你本人登录自己的公众号后台之后，把**你自己**账号下已经发布的文章搬到**你自己**的电脑上。没有你的登录、没有你的操作，微档什么也拿不到。

| 问题 | 大规模采集工具 | 微档 |
|---|---|---|
| 抓别的公众号发布的内容 | 可能大量采集 | **不支持**——只导出当前登录账号本人的文章 |
| 聚合多个公众号的数据 | 常见 | **否**——每次只处理你自己这一个账号 |
| 绕开微信官方的验证码/风控 | 可能 | **不做**——遇到验证码交给你本人处理 |
| 数据经过开发者的服务器 | 可能 | **不经过**——本地直连微信后台，本地写文件 |

详见知档的 [DISCLAIMER.md](https://github.com/zhangyingfeng/zhi-dang/blob/main/docs/DISCLAIMER.md) 和 [ACCEPTABLE_USE.md](https://github.com/zhangyingfeng/zhi-dang/blob/main/docs/ACCEPTABLE_USE.md)，微档沿用同样的原则。

这是独立开发的非官方项目，与微信/腾讯不存在隶属、合作、授权或认可关系。

## 目前的状态：能跑通端到端，还没打包成正式发布版

微档已经用一个真实公众号账号完整跑通过一次"扫码登录 → 导出到本地文件"：登录窗口、token 捕获、接口 relay、列表/正文抓取、Markdown/Word 落盘都验证过。发布/打包（把服务端编译成独立运行的 sidecar 二进制、代码签名、正式图标）还没做，目前只能用 `npm run tauri dev` 跑开发态；也还没真的触发过验证码/风控。技术方案的选择理由、已验证和未验证的细节，写在 [docs/DESIGN.md](docs/DESIGN.md) 里。

## 和知档的关系

微档复用了知档的架构和一部分可以直接迁移的通用代码（`Exporter`、`ContentSource` 接口、通用工具函数），这些文件版权仍归属同一作者，按 MIT 协议保留、按微信场景做了改写（比如去掉了知乎"回答/文章"的两分类，统一成"文章"）。公众号内容获取部分则是全新实现。

开发过程中参考了以下开源项目的**接口形状和实现思路**（不是代码本身）：

- [wechat-article/wechat-article-exporter](https://github.com/wechat-article/wechat-article-exporter)（MIT）——公众号后台管理接口的调用方式
- [tmwgsicp/wechat-download-api](https://github.com/tmwgsicp/wechat-download-api)（AGPL-3.0）——反风控/验证码识别的处理思路

微档本身按 MIT 协议开源，因此**没有照抄这两个项目的源代码**，尤其是 AGPL-3.0 协议的 wechat-download-api——如果直接并入它的代码，微档就必须整体转为 AGPL 协议，这不是这个项目想要的授权方式。两者都只作为"别人是怎么解决这个问题的"参考，具体实现是独立编写的。
